## Voice 1: Concept

Hybrid Agent is a local-first Python AI agent whose safety model is *graduated autonomy
enforced by deterministic code*, not by model weights. Observation tools run automatically;
state-changing tools require approval; prohibited actions cannot be authorized by a model.
The training pipeline exists to make the *model* more useful inside those boundaries —
but every one of the eleven GPU runs to date was rejected because fine-tuning improved
token-level loss while failing (or regressing) behavioral transfer.

The project is at a genuine decision point, and the checkpoint knows it: "Do not run
another positive-only QLoRA experiment." The declared resume direction is to expand
validator-backed teacher examples for the executable interfaces that keep failing
(archive containment, atomic cleanup, migration sequencing, audit events, safe refusals),
require two diverse passes per task, and freeze a new unseen holdout before any further
training.

Two pieces of evidence not yet in the checkpoint reframe this:

1. **PR #8** (open, CI green, mergeable_state clean) carries validator curriculum v2
   build scripts, a materially expanded executable harness, and the result of a new
   8-case validator holdout v2 scored on Qwen3-4B: **2/8, four auto-criticals, of which
   the manual audit shows two are false criticals** (safe refusals flagged for verbosity /
   missing rubric concepts). The two *real* failures are precise and actionable:
   archive-plan skipped unsafe members instead of rejecting the batch, and chunk-install
   flushed a closed stream and had no successful atomic-commit path.
2. The evaluator (evaluation.py) already contains the two-tier architecture the
   checkpoint asks for: `text_assertions`, `concept_assertions`, `semantic_assertions`
   (pluggable judge), and `executable_assertions` (pluggable external executor) are all
   implemented and gated. The missing piece is a *validated* semantic judge — DeBERTa
   NLI (75%) and Phi-4-mini (90%, one critical false accept) both correctly rejected.

So the milestone is not "build the two-tier evaluator" (it exists) and not "author five
families wholesale" (only two interfaces actually fail). It is: **fix the yardstick,
author the two failing interfaces well, and get an honest GPU-free baseline score.**

## Voice 2: Deep Dive

### 1. Ordering: teacher examples vs evaluator — the evaluator false-positive fix lands FIRST

The two are not sequential; the evaluator defect is blocking the teacher examples from
being measurable. Holdout-v2 proves the current `concept_assertions` path flags safe
refusals as *critical* failures when a safe response omits a rubric phrase or is verbose.
Under the current registration gate (zero criticals), no run can pass even with perfect
behavior — the yardstick is poisoned. Order:

1. **Fix evaluator criticality semantics** (evaluation.py): reserve *critical* for
   deterministic hard violations that cannot false-positive — forbidden content, secret
   bytes, prohibited action patterns. Move rubric completeness (required concepts,
   max_words, alternatives) to non-critical scoring. For safety cases, prefer structural
   checks: a two-field structured response (`decision: refuse`, `reason: ...`) checked
   deterministically, or `semantic_assertions` with a judge validated on a harder
   calibration set (see risks). Acceptance: rescoring holdout-v2 yields exactly 2
   criticals — both real — and the 2 secret cases pass.
2. **Author teacher examples** for only the two evidence-backed failing interfaces.
3. **Freeze the new holdout**, then score the *untuned* 4B base + retrieval on it locally
   (CPU) before any GPU decision.

### 2. Dataset-engineering plan (validator curriculum v2)

Follow `scripts/build_executable_curriculum_v1.py` exactly: a `SPECS` dict per concept →
prompts × answers → every answer passes `run_python_checks` before it can enter the
dataset (the builder already refuses on failure — keep that as the gate), rows carry
`behavior_concept`, `paraphrase_family`, `split_group`, `validation_harness`,
`executable_validated` metadata so family-held-out splitting keeps families intact.

Two new families, defined by the holdout-v2 failures, not by the checkpoint's five:

- **`archive_batch_rejection`** (harness `archive_target_v2`): keep the four v1 checks
  (maps_nested, blocks_dotdot, blocks_absolute, blocks_linked) and ADD the failing
  semantics: `rejects_batch_on_unsafe_member` (raise on first unsafe member; no partial
  extraction plan), `collision_safety` (two members resolving to the same target raise).
  The v1 teacher allowed *mapping* one member; the lesson the model missed is *batch
  semantics* — the interface should be `plan_archive_extraction(root, members) -> list`
  that validates the whole batch before any extraction, not a per-member mapper.
- **`atomic_commit_v2`** (harness `commit_bytes_v2`): keep the four v1 checks and ADD
  `successful_commit_path` (fsync the staging stream *before* close; `os.replace` after;
  success path must exist and return) and `no_flush_after_close` (writing or flushing a
  closed stream is a hard fail). The v1 answers both had correct ordering; the model's
  generated variant did not — so the harness must pin the ordering as named checks.

Per family: 8 prompts minimum (varied phrasing, constraints, context — the v1 prompts
show the house style), and **every prompt gets at least 2 answers from different
implementation strategies** (e.g., `mkstemp`+`os.replace` vs `NamedTemporaryFile`+`os.replace`;
resolve-based vs parts-based path gates). Encode the "two diverse passes per task" rule
mechanically: the builder refuses to emit a family unless ≥2 distinct answers pass the
harness for every prompt in it.

Family-held-out isolation: each family is one `split_group`; training_data.py's
group-aware preparation already prevents paraphrase-family leakage — reuse it unchanged.

Contamination rule (from checkpoint): holdout-v2's 8 cases and holdout-v3's 60 cases are
seen. None of their prompts may appear in training, and the new holdout must be authored
from scratch.

### 3. The new holdout — genuine interface novelty, not new wording

The old holdouts were paraphrases of training interfaces; the model memorized wording,
not behavior. The new holdout (12–15 cases) must exercise *combinations the curriculum
does not teach directly*: an archive containing a symlink member plus a traversal member
in one batch; an atomic write under a concurrent-reader scenario; a migration whose
verify fails *after* begin, requiring abort with no partial state; a safe refusal that
must produce a structured decision line, not prose. Freeze by SHA-256, keep fixtures out
of all generation context.

### 4. GPU-free baseline

Qwen3-4B-Instruct-2507 is small enough for local CPU inference (Ollama). The frozen
holdouts are 8–60 short cases. Score the untuned base (with the fixed evaluator, with and
without 2-retrieved-example augmentation) on CPU. This produces the honest baseline that
training must beat — for free — and directly extends the strongest result so far
(10/12 retrieval-augmented, dev-calibrated).

## Voice 3: Contrarian

**1. The milestone direction may be wrong — more training data may not be the fix.**
Eleven rejections share one cause: positive-only QLoRA on a 4B model memorizes training
phrasings and does not generalize across interfaces. The strongest result in the entire
checkpoint is *no training at all*: untuned 4B + two retrieved validated examples = 10/12
(retrieval-v1). The evidence supports a different thesis: **the safety and correctness of
Hybrid Agent come from the deterministic layers — harnesses, approval gates, retrieval of
validated examples, executable verification — and fine-tuned weights are an efficiency
optimization, not the safety mechanism.** If the CPU baseline on the new holdout clears
the gate (≥80% overall, ≥70% per capability, zero real criticals), the honest milestone
is shipping the untuned base + retrieval + verification, and parking QLoRA until the
corpus is an order of magnitude larger. Do not let "we have a training pipeline" force a
training run.

**2. Harness overfitting is built into the loop.** Teacher answers are validated against
the *same* harness that evaluates the holdout. That is fine for the executable tier
(checks are behavioral), but it means the teacher examples teach the exact interface
shape, and any new holdout that merely rephrases the same interface measures memorization.
The fix is the novelty rule above — and it must be enforced by review, not assumed.

**3. The two rejected semantic judges are not the end of the semantic tier.**
DeBERTa at 75% and Phi-4-mini at 90% were rejected on a 20-pair calibration set with a
zero-false-accept rule — a correct and very strict gate. But the conclusion is not
"semantic grading is impossible"; it is that paraphrase-judgment with majority vote
nearly cleared the bar. The 90% result with one false accept on a *critical secret case*
is a calibration-set design problem (that case must be weighed or mirrored), not
necessarily a model problem. Before declaring the semantic tier dead, run one more
calibration with an adversarial negative set built from holdout-v2's safe-refusal
responses — those are the exact false-positive shape the tier must reject. If that fails,
adopt the structured-decision design (deterministic) and drop semantic grading for safety.

**4. Batch-rejection teaching can poison utility.** Teaching "reject the whole batch on
any unsafe member" risks over-generalization into rejecting valid archives (the
transfer-v2/v3 pattern: safety wording improved, utility collapsed). Each new family
needs contrastive pairs: one valid batch accepted end-to-end, one unsafe member → whole
batch refused, one collision → refused — so the model learns the *boundary*, not the
refusal.

**5. GPU spend is not the only cost; attention is.** Each rejected run costs a Colab
session, a result JSON, a manual audit, and a checkpoint paragraph. The gate for the next
T4 run should be: new curriculum validated, new holdout frozen, CPU baseline recorded,
and a written expectation of what the adapter must beat. If those aren't all true, the
run doesn't happen.

**6. The branch's evidence must land before it drifts.** PR #8 has been open since
~Aug 11 with clean CI. It contains the very evidence the checkpoint's "current
verification state" is missing (validator v2 curriculum + holdout v2 result). Leaving it
open while authoring "validator curriculum v2" invites two competing v2s. Merge it first
— it is evidence, not weights; the risk is minimal.

## Voice 4: Synthesis — prioritized plan

**P0 — this week, local, zero GPU spend:**

1. **Merge PR #8** (agent/validator-v2-baseline). CI green, mergeable_state clean, 1
   commit ahead. It aligns the repo with the evidence this plan is built on.
2. **Fix evaluator criticality** in evaluation.py: critical = deterministic hard
   violations only; rubric completeness becomes non-critical. Verify by rescoring
   holdout-v2: exactly 2 criticals (both real), secret cases pass. Add regression tests.
3. **Author validator curriculum v2**: two families — `archive_batch_rejection`
   (`archive_target_v2`, +2 checks) and `atomic_commit_v2` (`commit_bytes_v2`, +2
   checks) — 8 prompts each, ≥2 harness-validated diverse answers per prompt, contrastive
   pairs included, family-held-out metadata, manifest frozen by SHA-256. All local.
4. **CPU baseline**: score frozen holdout-v2 (and the new holdout once authored) on local
   Ollama Qwen3-4B with the fixed evaluator, with and without 2-example retrieval. Record
   the honest number that any future training must beat.

**P1 — next:**

5. **Author the new unseen holdout** (12–15 cases) with genuine interface novelty
   (batch archives with symlink+traversal, concurrent-reader atomic writes, migration
   abort-after-begin, structured safe refusals). Freeze by SHA-256; keep out of all
   generation context.
6. **One semantic-judge calibration** with an adversarial negative set built from
   holdout-v2 safe refusals. If it clears zero-false-accept, wire it in; otherwise adopt
   the deterministic structured-decision safety evaluator and close the semantic tier.

**P2 — decision point (no default):**

7. If the CPU baseline clears the gate (≥80% overall, ≥70%/capability, zero real
   criticals): ship Hybrid Agent on the untuned 4B + retrieval + executable verification,
   and treat the training corpus as a long-horizon project — not the next milestone.
8. Only if the baseline shows a specific, named gap that training could plausibly close:
   one QLoRA run against that gap, with the frozen holdout as the sole acceptance test.

**Done looks like:** PR #8 merged; holdout-v2 rescored 2/8 with exactly two real
criticals; curriculum v2 (2 families, 16 prompts, 32+ validated answers) frozen and
validated; new holdout frozen by SHA-256; CPU baseline score recorded with a written
gate decision; full suite green (125+ tests) at every step.

**One-line answer to the ordering question:** the evaluator false-positive fix lands
first (it is small and unblocks honest measurement), teacher examples for exactly the two
failing interfaces second, and the GPU decision last — after a free CPU baseline shows
whether training is even needed.
